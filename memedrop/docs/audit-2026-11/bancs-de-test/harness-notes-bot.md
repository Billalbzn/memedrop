## limitations
Only discord.js, ws and dotenv are replaced, and only for CommonJS require (Module._resolveFilename); ESM `import` of them is not intercepted. Any new third-party dependency must resolve from the bot dir (no npm install here). The bot entry point is package.json "main" (default index.js). discord.js is a fake of the v14 surface: it reproduces caching (cache-first fetch, interaction users and members cached, no member eviction), captureRejections, 5 ms API latency, the 2000-character limit and 10062 for expired tokens. It does not enforce the 3 s ack deadline, rate limits, permissions or intent-gated events. Time: Date and performance.now are virtual. Timers of 10 s or more are virtual when created from code under the bot dir (global setTimeout/setInterval, require('timers'), timers/promises.setTimeout); shorter timers run in real time. process.hrtime or other scheduling mechanisms would not be controlled. Upstream: only global fetch to translate.google.com/translate_tts is mocked; other hosts or https.request are recorded as unexpected and fail; the child has no proxy environment. Not compared: logs (saved in <out>.log) and HTTP framing (chunked or not). Discord API counters are informational unless --strict-counters. The exact deferReply/reply/editReply sequence is compared strictly unless --loose-acks. Order across channels within one step (for example interaction reply vs overlay message) is not compared because it is inherently racy; order within each channel is. Step ids are positional: if the scenario is edited, the baseline must be regenerated. selftest.js patches today's code text and will report 'patch matches 0 times' once the code changes. p5 and p6 end in a bot crash with the current code; after fixes those processes continue and add steps, which are expected diffs. A pairing code that happens to equal '000000' (probability about 5e-5 per run) would be mislabelled <UNISSUED_CODE>. Not covered: PORT/WS_PORT fallback, a missing DISCORD_TOKEN, gateway reconnects, guildCreate/guildDelete, and the Electron and Android clients (they need their own harnesses).
